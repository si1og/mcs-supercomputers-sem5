# Курсовая работа: параллельная обработка данных с MPI и OpenMP

## Общая идея

MPI — это стандарт для обмена сообщениями между параллельно работающими процессами. Его реализации, например Open MPI, позволяют явно разделить вычисления между несколькими процессами, синхронизировать их и организовать обмен данными.

Одна и та же программа запускается в нескольких экземплярах: на каждом вычислительном узле работает один или несколько процессов. Каждый процесс получает уникальный номер — **ранг** (`rank`). Общее количество процессов хранится в `size`.

Типичная MPI-программа имеет следующую структуру:

```cpp
#include <mpi.h>

int main(int argc, char** argv) {
    MPI_Init(&argc, &argv);

    int rank = 0;
    int size = 0;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    // Вычисления и обмен данными между процессами

    MPI_Finalize();
    return 0;
}
```

Узким местом MPI-программ часто становится передача сообщений. Поэтому данные желательно распределять крупными блоками и по возможности уменьшать количество обменов между процессами.

## Основные виды коммуникаций

Операции обмена данными в MPI можно разделить на две группы:

1. **Точечные коммуникации** — обмен между конкретными отправителем и получателем.
2. **Коллективные коммуникации** — операции, в которых участвует вся группа процессов.

### Точечные коммуникации

Блокирующие операции:

- `MPI_Send` — отправить сообщение;
- `MPI_Recv` — получить сообщение.

При их вызове выполнение процесса приостанавливается до завершения соответствующей операции. Осваивать MPI удобнее именно с блокирующих функций.

Неблокирующие варианты:

- `MPI_Isend`;
- `MPI_Irecv`.

Они позволяют продолжить вычисления, пока обмен данными ещё выполняется. Однако необходимо отдельно дождаться завершения операции, например с помощью `MPI_Wait` или `MPI_Test`, иначе сообщение может быть обработано некорректно.

### Коллективные коммуникации

- `MPI_Bcast` — один процесс рассылает одинаковые данные всем остальным;
- `MPI_Scatter` — исходный набор данных делится на блоки, и каждый процесс получает свой блок;
- `MPI_Gather` — данные со всех процессов собираются в общий буфер одного процесса;
- `MPI_Reduce` — результаты всех процессов объединяются с помощью заданной операции, а итог передаётся одному процессу, обычно с рангом `0`;
- `MPI_Allreduce` — то же объединение результатов, но итог получают все процессы;
- `MPI_Alltoall` — каждый процесс отправляет отдельные данные каждому другому процессу; в этой работе использовать не требуется.

## Задание

Нужно выбрать датасет и реализовать содержательную операцию над его данными. Результат обработки должен иметь практический смысл, то есть недостаточно просто прочитать или переслать данные. Это может быть арифметическая или агрегатная обработка по одному или нескольким интересным атрибутам. Например, для графовых данных можно искать плотные подграфы, соответствующие тесно связанным социальным группам.

Рекомендуемый объём датасета — около **200 МБ**. Подходящий набор данных можно взять, например, с Kaggle.

Для выбранной задачи необходимо подготовить и последовательно сравнить несколько режимов выполнения:

1. **Последовательная реализация.** Она служит эталоном для проверки результата и базовой точкой при измерении времени выполнения.
2. **Параллельная реализация на одном узле с OpenMP.** Нужно измерить, как меняется время выполнения при разном количестве потоков.
3. **Распределённая реализация с MPI на двух узлах без многопоточности.** Для OpenMP через переменную окружения задаётся один поток, поэтому на каждом узле MPI-процесс работает в однопоточном режиме.
4. **Гибридная реализация MPI + OpenMP.** Сначала данные и вычисления распределяются между узлами с помощью MPI, затем внутри каждого MPI-процесса включается распараллеливание по потокам OpenMP.

Во всех режимах необходимо зафиксировать два показателя:

- полученный результат, чтобы проверить корректность относительно последовательной версии;
- время выполнения, чтобы оценить ускорение от OpenMP, MPI и их совместного использования.

Следует учитывать, что при параллельных вычислениях результат операций с плавающей точкой может немного зависеть от числа потоков и порядка выполнения операций.

Итогом работы должны стать полезный результат обработки выбранного датасета, замеры времени для всех реализаций и локальный Git-репозиторий с исходным кодом.

## Запуск и окружение

На одном узле может находиться среда разработки, а на остальных достаточно установить необходимое окружение для запуска программы.

Полезные пакеты:

- `g++` — компилятор C++;
- `libgomp1` — среда выполнения OpenMP;
- `libopenmpi-dev` — заголовочные файлы и библиотеки Open MPI.

Количество потоков OpenMP задаётся переменной окружения:

```bash
OMP_NUM_THREADS=4 ./program
```

Обычно число потоков выбирают равным числу доступных физических или логических ядер, после чего проверяют производительность экспериментально.

MPI-программа запускается через `mpirun`. В команде можно указать список вычислительных узлов, число процессов и передать переменные окружения. Нужно провести как минимум два варианта запуска:

- один процесс на каждом узле;
- два процесса на каждом узле.

Перед началом основной работы полезно собрать и запустить примеры из `ParallelComputationExamples`, проверить связь между узлами и убедиться, что простые MPI-программы корректно работают во всех требуемых конфигурациях.

Исходный код можно хранить в локальном Git-репозитории; разные реализации при желании можно разнести по отдельным веткам.
